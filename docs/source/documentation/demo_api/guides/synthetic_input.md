# Synthetic Input

The FlashDreams synthetic input system provides infrastructure for:

- Deterministic inputs fed into a FlashDreams `IApplication` for packaging,
  QA, and benchmark purposes.
- **Unimplemented:** Recording and serializing `IApplication` inputs.
- **Unimplemented:** A stable textual format for `UserInputEvent` generation
  on the fly through an `IClientWindow`.

## Run an app with Synthetic Input

Add `--synthetic-input-file INPUT_FILE.json` to the system arguments of a
run-command:

```bash
uv run flashdreams-run-v2 DEMO_MODEL_SLUG \
  --mode mp4 \
  --output-path replay.mp4 \
  --total-model-steps 120 \
  --backpressure-mode block \
  --presentation-mode on_demand \
  --synthetic-input-file inputs.json
```

`--backpressure-mode block` blocks `model_loop` when running faster than
`ui_loop` to avoid dropping model outputs. `--presentation-mode on_demand`
ensures we block presentation when running faster than `ui_loop` to avoid
dropping UI outputs. Together, these options keep `model_loop`, `ui_loop`, and
presentation all consistent in pacing with each other. See the
[CLI reference](../../cli.md#default-demo-session-overrides) for details.

## Descriptor format

### Example `inputs.json`

```json
{
  "version": 1,
  "events": [
    {
      "on": "ui_loop",
      "at": 0,
      "event": {"type": "keyboard", "key": "w", "state": "Pressed"}
    }
  ]
}
```

On step zero of our `ui_loop`, we will emit a `KeyboardUserInputEvent` of
state: `key="w"` `state="Pressed"`.

### Options for descriptor format

| Component | Purpose | Value |
| --- | --- | --- |
| `version` | Descriptor format version | Should be integer `1` |
| `events` | List of `UserInputEvent` objects to generate at some cadence | `on`, `at`, `event` |
| `on` | Determines how to interpret `at` | `"ui_loop"` |
| `at` | Cadence to trigger event | Non-negative integer. For `ui_loop`, specifies the step number an input event must be released on. |
| `event` | `UserInputEvent` payload | Registered `type` of a `UserInputEvent` and fields for that event; `timestamp` is autogenerated at insertion time |

### Examples of `event` definitions

#### Keyboard event

```python
@dataclass(frozen=True, slots=True, eq=False)
class KeyboardUserInputEvent(UserInputEvent):
    """User input event for a keyboard."""

    @classmethod
    def get_type_name(cls) -> str:
        """Return the event type name."""
        return "keyboard"

    key: str
    """Identifier of the key this event refers to, e.g. ``"r"``."""
    state: KeyboardInputState
    """State transition reported for ``key``."""
```

```json
{"type": "keyboard", "key": "w", "state": "Pressed"}
```

`type` matches the class's `get_type_name()`. `key` and `state` are required.
`state` accepts `"Pressed"` or `"Released"`.

#### Mouse event

```python
@dataclass(frozen=True, slots=True, eq=False)
class MouseUserInputEvent(UserInputEvent):
    """User input event for a mouse."""

    @classmethod
    def get_type_name(cls) -> str:
        """Return the event type name."""
        return "mouse"

    action: Literal["move", "button", "wheel"] = "move"
    x: float = 0.0
    y: float = 0.0
    button: int = 0
    pressed: bool = False
    wheel_x: float = 0.0
    wheel_y: float = 0.0
```

```json
{"type": "mouse", "action": "button", "button": 0, "pressed": true}
```

This presses mouse button `0`. Omitted fields use the defaults defined by the
class.

#### Reset event

```python
@dataclass(frozen=True, slots=True, eq=False)
class ResetUserInputEvent(UserInputEvent):
    """The client asked to start the run over."""

    @classmethod
    def get_type_name(cls) -> str:
        """Return the event type name."""
        return "reset"
```

```json
{"type": "reset"}
```

`reset` requires no additional fields.
