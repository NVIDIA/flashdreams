Contributing
============

This page is a quick-orientation for would-be contributors. The
authoritative documents live in the repository root:

- `CONTRIBUTING.md <https://github.com/NVIDIA/flashdreams/blob/main/CONTRIBUTING.md>`__
  — the full contribution policy: DCO, governance, review, licensing.
- `DEV.md <https://github.com/NVIDIA/flashdreams/blob/main/DEV.md>`__
  — local development details: versioning, PyPI publishing, package
  inventory.

Please read those before sending a non-trivial pull request. Everything
below is a map, not a replacement.

What's in CONTRIBUTING.md
-------------------------

The canonical doc covers the full contribution policy. Specific sections
worth bookmarking:

- **DCO sign-off** — every commit needs ``git commit --signoff``; no
  separate CLA. See
  `CONTRIBUTING.md#developer-certificate-of-origin-dco
  <https://github.com/NVIDIA/flashdreams/blob/main/CONTRIBUTING.md#developer-certificate-of-origin-dco>`__.
- **The PR flow** — fork, small focused PRs, tests, signed-off
  commits, design issue first for large changes. See
  `CONTRIBUTING.md#pull-request-flow
  <https://github.com/NVIDIA/flashdreams/blob/main/CONTRIBUTING.md>`__.
- **CI tier markers** — every test carries exactly one of
  ``ci_cpu`` / ``ci_gpu`` / ``manual``; a pytest plugin enforces this
  at collection. See
  `CONTRIBUTING.md#testing
  <https://github.com/NVIDIA/flashdreams/blob/main/CONTRIBUTING.md>`__.
- **Coding conventions** — Python 3.12+, ``ruff`` formatting via
  pre-commit, SPDX headers on new files. See
  `CONTRIBUTING.md#coding-conventions
  <https://github.com/NVIDIA/flashdreams/blob/main/CONTRIBUTING.md#coding-conventions>`__.
- **Project governance** — who maintains the project and how
  decisions get made. See
  `CONTRIBUTING.md#project-governance
  <https://github.com/NVIDIA/flashdreams/blob/main/CONTRIBUTING.md#project-governance>`__.

What's in DEV.md
----------------

Local development reference: workspace install (``uv sync``), the
``flashdreams-run`` CLI, lint and type-check commands, and the
versioning / PyPI publishing pipeline. Start here if you want a
hands-on bootstrap from a fresh clone. See
`DEV.md <https://github.com/NVIDIA/flashdreams/blob/main/DEV.md>`__.

Documentation contributions
---------------------------

The site you are reading is built from ``docs/source/`` with Sphinx.
A few notes specific to doc PRs:

- ``warningiserror = True`` — a broken ``:doc:`` or ``:ref:`` link
  fails CI. Use ``uv run sphinx-build -b html -W docs/source build/html``
  to reproduce locally.
- The site uses a shared design system documented in
  ``docs/site-design-system.md`` (outside the build tree). Prefer
  composing the components defined there over inline CSS or ad-hoc
  classes.
- API reference pages are generated by autodoc from docstrings. Doc
  fixes that touch ``apis/*.rst`` should generally be paired with a
  docstring fix in the source module.

.. admonition:: New components or assets?
   :class: fd-callout

   If you find yourself reaching for inline ``style=""`` attributes or
   new ``_static/`` files, please open an issue first and tag it
   ``site`` — the site design system is intentionally narrow so the
   look stays consistent.

Filing security reports
-----------------------

Please **do not** file security issues as public GitHub issues. Follow
NVIDIA's coordinated disclosure process at
`nvidia.com/security <https://www.nvidia.com/en-us/security/>`__.
