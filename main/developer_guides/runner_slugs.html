Application slugs and model adapter dispatch#

Runnable applications live under apps/. Model integrations do not own demo implementations or runner shims; they expose small bindings from integrations_v2/<model>/apps/<app>/adapter.py.

Application discovery#

Each model package registers the applications it supports through the flashdreams.applications_v2 entry-point group. For example, OmniDreams binds regular and performance-tuned variants of the reusable application:

[project.entry-points."flashdreams.applications_v2"]
"interactive-drive-omnidreams" = "omnidreams.apps.interactive_drive.adapter:create_app"
"interactive-drive-omnidreams-perf" = "omnidreams.apps.interactive_drive.adapter:create_perf_app"

Action2V can be bound by more than one model without duplicating the application:

# integrations_v2/lingbot/pyproject.toml
"action2v-lingbot" = "lingbot.apps.action2v.adapter:create_app"

# integrations_v2/hy_worldplay/pyproject.toml
"action2v-hy-worldplay" = "hy_worldplay.apps.action2v.adapter:create_app"

Ownership boundary#

The reusable package owns UI behavior, argument parsing, application sessions, and presentation. The model package owns its implementation and canonical configuration:

apps/<app>/
  <app>/...

integrations_v2/<model>/
  config.py
  impl/...
  apps/<app>/adapter.py

config.py is the only Python module at the integration root. The adapter imports model defaults and hooks only from ...config, constructs the reusable application, and contains no model implementation or launch orchestration.

Adding or changing a binding#

  1. Add reusable behavior to apps/<app>/.

  2. Add model implementation to integrations_v2/<model>/impl/.

  3. Define the model’s pipeline configs, defaults, and hooks in integrations_v2/<model>/config.py.

  4. Add the minimal adapter at integrations_v2/<model>/apps/<app>/adapter.py.

  5. Register the adapter under flashdreams.applications_v2.

  6. Run the CPU ownership and import checks:

uv run pytest -m ci_cpu \
  apps/t2v/tests/test_integration_apps.py \
  integrations_v2/<model>/tests

Do not add runner.py, launch.py, runtime.py, model_session.py, or a model-specific demo package to bridge the application and integration layers.
